# 项目技能库

这里存放 Wishtaday 办公室的技能资源，供私人秘书和部门智能体在后续执行层接入后使用。

当前已建立两类技能编写目录，并新增网页技能目录与本地下载包映射。目录和下载包不等于已安装技能；放入文件不会自动安装、运行或分配给员工。

## 目录

```text
skills/
├── catalog/                  用户CSV目录、下载映射与核对报告
├── packages/                 原始来源压缩包，仅下载，不安装
├── capabilities/             单项技能：完成一个明确动作
│   └── _template/            单项技能编写模板，不作为实际技能加载
│       ├── SKILL.md          用途、输入、输出、步骤和失败处理
│       ├── scripts/          可选的执行脚本
│       └── templates/        可选的表格、报告等输出模板
└── workflows/                流程技能包：组织多项能力完成一个目标
    └── _template/            流程编写模板，不作为实际技能加载
        ├── SKILL.md          步骤顺序、依赖、协作与验收条件
        ├── scripts/          可选的流程辅助脚本
        └── templates/        可选的交接单、结果汇总等模板
```

- **单项技能**：例如图片文字识别、文本提取、表格对比；可独立使用，也可被流程引用。
- **流程技能包**：例如资料识别 → 内容整理 → 表格核对 → 归档；复用单项技能，不复制同一套代码。

以上例子用于说明分类，尚未实现。

## 添加一个技能

1. 根据用途，复制对应的 `_template` 目录到同一级目录。
2. 用小写英文与连字符命名，例如 `table-compare`；单项技能和流程使用不同的名称。
3. 填写 `SKILL.md`（技能说明文件），替换所有“待填写”和示例占位内容。
4. 按实际需要添加脚本和模板；不需要的子目录可以删除。
5. 记录依赖和验证方法，用样例确认输入、输出及失败行为，再接入后续技能安装与执行模块。

`SKILL.md` 顶部的 `name` 是稳定名称，`description` 描述适用任务。类别由目录决定。当前不规定额外的机器执行清单格式，后续按实际执行模块确定，避免把说明模板误当作已实现的运行协议。

## 与员工和任务的关系

预期链路：老板交代目标 → 秘书拆分任务 → 部门智能体选择获准技能 → 执行单项技能或流程 → 返回结果与任务状态。

技能内容与人员资料分开：员工通过技能名称引用能力，同一项能力可供多个员工使用。员工姓名或部门改动，不需要移动或复制技能文件。

本目录仅存放项目维护的公共技能资源。企业上传内容、客户资料、运行结果和密钥不放进这里；后续上传存储和调用权限按企业隔离。不要在技能文件中写入账号密码或 API 密钥，脚本也不得绕过现有登录和租户权限。

## 后续接入

- 网页目录已接入；用户上传并安装到当前企业已实现，记录与原始包保存在数据库，见 `docs/ARCHITECTURE.md`。600项目录已支持逐项安装，按目录编号定位原包并保存到当前企业；同一项重复安装不会新增记录。
- 技能与员工的绑定、按企业授权。
- 模型工具调用、流程执行、任务状态和结果记录。

部署镜像现有构建规则会复制项目目录，本目录未被排除；这不代表云端已经支持技能执行。

## 下载与目录维护

现有600条目录来自用户提供的 CSV。`scripts/download-skill-catalog.py` 下载公开来源包；`scripts/recover-skill-downloads.py` 尝试从原仓库历史找回旧条目；`scripts/download-skill-subsets.py` 下载大型来源的指定技能目录；`scripts/finalize-skill-catalog.py` 合并补齐记录及英文说明；`scripts/verify-skill-catalog.py` 校验对应关系。下载及历史找回脚本会生成下载记录，运行前应备份当前目录映射，不能在已有独立补齐结果时无意覆盖。

这600项来源包只保存在 `packages` 中；`capabilities` 和 `workflows` 仍只有自建模板。用户通过页面上传或从目录选择安装的技能独立保存在数据库的企业私有安装记录中，不写入这里或全局技能目录。
