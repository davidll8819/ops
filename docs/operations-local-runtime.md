# 叶凡本机制作服务

已接入现有 Wishtaday 运营弹窗。访问 http://localhost:3000/，进入叶凡的运营工作台，在历史制作任务中打开“清晨的一杯咖啡”或“清晨的一杯咖啡 - 图片生成”，可查看保存的素材和执行记录。

## 本机运行与重启

在本仓库根目录使用 PowerShell 和 Node.js 24，先启动 Docker Desktop，再执行：

```powershell
node --env-file=.env scripts/operations-local.mjs start 74c7972b-41e9-4720-aaf4-465c686293b5
node --env-file=.env scripts/operations-local.mjs status 74c7972b-41e9-4720-aaf4-465c686293b5
```

本机配置已经建立；使用上述 status 命令核对当前状态。尚未配置 Windows 开机自动启动。重启电脑后需要执行上述 start 命令。Wishtaday 主程序另行启动：

```powershell
node --env-file=.env apps/api/src/server.mjs
```

正常停止制作服务：

```powershell
node --env-file=.env scripts/operations-local.mjs stop 74c7972b-41e9-4720-aaf4-465c686293b5
```

停止前会暂停接收新任务并检查正在制作的任务；有任务时拒绝停止并恢复接收。停止成功后保留数据库和素材。脚本只控制入口文件及企业配置均匹配的进程，先停 AI 服务，再停支持服务。

## 模型适配与提交保护

- 保留企业选择的图片模型 `alibaba/wan2.6-image` 和视频模型 `wan-2.7`。
- 当前服务商图片入口要求参考图，并未接受测试的纯文字参数。文字生图由本机适配层自动附上中性白色底图，再调用该模型的图片编辑接口；用户仍可直接输入文字。用户提供参考图时使用其参考图。
- 图片 SDK 自动重试关闭。任务分别持久保存图片、视频的未决提交状态，以原子方式预约；工具重建、继续对话后也不会因为状态丢失重复提交。结果未知时查询原任务。
- 原弹窗支持读取真实 SDK 的图片资源链接及已完成视频结果，历史任务恢复后仍可预览。只为操作员配置的素材来源增加图片和媒体 CSP 许可。
- 本次只制作预览，没有发布到外部平台。

## 2026-10-19 视频规格修复

在原运营弹窗勾选“指定视频规格”，可选择 9:16 竖屏、16:9 横屏或 1:1 方形，以及 720p / 1080p。勾选后的规格优先于模型填写的参数；取消勾选并继续原任务会清除先前指定的规格。未勾选时按工作要求制作。

实际问题是服务商忽略顶层 `aspect_ratio` / `resolution`；它要求这两个字段同时进入 `extra_body`。已保留企业原模型，通过该映射真实生成两份约 5 秒视频：

| 验证 | 任务 | 实际尺寸 |
| --- | --- | --- |
| 参数诊断 | `vg_-hN270mSofBSJsT0BPPUUHDo` | 720×1280 |
| 原弹窗完整提交 | `6ad58d4c34c4a4d78f39365c`，媒体 `6ad58d7534c4a4d78f393671` | 1080×1920 |

两份成品均直接由模型生成，没有裁剪或拉伸。未逐一付费实测所有比例与分辨率的组合。验收记录在本机 `.local/video-format/`，不随源码公开上传。

每份视频保存自己的请求规格与真实尺寸，不会被最终回复中重复的素材链接覆盖。探测临时失败后复用已保存素材，不再次上传或生成。任务详情按用户和原任务直接读取关联视频，即使文字模型在收尾时达到当日额度，已经生成的视频仍可独立查询；保留原对话的失败状态，不伪造成功，也不擅自提高企业额度。视频仍在制作时由工作台直接查询原任务。
