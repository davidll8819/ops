# 企业统一模型入口

## 项目地图与本次边界

老板/员工 → 现有 Office 登录与企业权限 → 部门 → strong / fast / cheap 档位 → Office 模型入口 → 4YI。

秘书任务草稿 → 用户确认派发 → 持久队列按前置任务关系执行 → 已完成的文字／图片交接给后续部门 → 成果展示与归档。设计任务按要求走文字或图片模型；网页只负责派发和展示，不再逐项调用执行接口。

运营部 → 保留的 AiToEarn Agent、分镜、图片/视频工具与素材数据库 → Office 模型入口 → 4YI。
运营部发布请求 → Office 发布审批与防重复提交 → AiToEarn 原发布流程 → 平台回执。

本次复用企业设置、原始生成适配器、原始数据结构、签名调用桥；新增档位路由、加密企业密钥、文字用量账本。没有重新实现视频生成算法。私人秘书对话已接入企业文字模型，支持用户偏好与模型生成的任务草稿；AWS 自定义助手仍保留原后端路径。

## 文件地图

- `config/company.example.yaml`：与用户给出的三层结构一致的参考配置，无真实密钥。实际企业设置通过页面保存到 PostgreSQL，不会自动读取示例文件。
- `apps/api/src/operations/policy.mjs`：配置校验、部门档位、企业专属环境变量命名。
- `apps/api/src/operations/gateway.mjs`：服务器读取模型列表、部门文字请求、AiToEarn 私有模型转发与流式计量。
- `apps/api/src/department-engine.mjs`、`task-dependencies.mjs`：后台部门任务调度、前置成果读取与交接记录；调研队列继续复用 `research/engine.mjs`。
- `apps/api/src/operations/task-service.mjs`、`task-media.mjs`：携带前序文字及真实图片提交运营任务；图片在运行服务就绪后上传为其可读取的素材，后台同步任务状态。
- `apps/api/src/operations/budget.mjs` 和 `database/migrations/006_model_budget.sql`：每日额度预占和结算，保留请求来源、模型、企业和可取得的用户 ID，不保存对话内容。
- `apps/web/src/saas/Settings.tsx`：双语设置界面。
- `scripts/export-operations-runtime.mjs`：导出独立运行服务的配置，AI 使用内部网关令牌引用，平台中转密钥运行时读取，不写入导出的配置。
- `scripts/run-operations-service.mjs`：运行**已构建**的原服务，为该企业注入运行所需凭据。不会部署基础设施、构建原服务或绑定平台。
- 原服务 `libs/common/src/utils/office-env.util.ts`：在原配置校验前解析完整 `${ENV_NAME}` 引用。

## 配置步骤

1. 设置页保留入口 `https://app.4yi.ai/api/v1`。填写 `/api/v1/models` 会自动规范化；读取模型时才请求该列表地址。本版本只接受已复用适配器的 `app.4yi.ai`，避免把供应商凭据发送到任意地址。
2. 企业所有者或管理员在「企业 AI API Key」输入密钥，在「平台中转 API Key」输入独立的中转账号密钥。服务端按企业进行 AES-256-GCM 加密存储；GET 设置接口只返回是否配置，不返回密钥。留空保持原值，输入新值替换。浏览器不写 localStorage，日志隐藏请求体。平台账号仍需分别授权。
3. 环境变量仍作为可选的部署默认值，已保存的企业密钥优先。没有保存值时，只读取当前企业专用变量，或 GATEWAY_TENANT_ID 明确绑定的单企业短变量。加密主密钥由部署人员保管并独立备份。
4. 点击读取模型列表；若刚填写新密钥，页面先保存再查询。列表只证明账号可见，不证明工具调用、图像或视频生成可用。运营部规划模型仍需兼容原 Anthropic 工具调用协议。六个选择项分别是 strong/fast/cheap（文字）、image（图片）、video（视频）、search（搜索），全部使用下拉列表。分类优先使用输出能力与 type/model_type，缺少元数据时按常见型号推断，未知型号单独标记。留空可保存，但对应生成请求会拒绝执行。部门可分别启用图片、视频、搜索，继承公司模型或单独指定。
5. 更新 Key 与档位后，已部署的运行服务会动态读取最新设置，不要求用户改 YAML 或手工重启。AI 经过 Office 网关；原 RelayClient 与 RelayExceptionFilter 通过企业签名接口读取最新平台中转密钥。版本 4 调用桥检查租户与发布审批能力，不再按每次配置 revision 要求重新部署。
6. 制作任务在用户确认分工后可以自动接续；对外发布独立停在待审批，`content_ops.need_confirm` 保留为 true。任务只要求草稿或预览时不得发布。缺少必要信息时询问，提交结果不明时保留记录并禁止盲目重试。
7. 技能只在技能库展示。「单体技能包」保留原目录；「流程技能包」下的「运营流程」打开共享「运营工作台」。智能体页不展示技能，只保留员工与职责，叶凡可打开同一工作台。
8. 账号备注不等于绑定。运行地址、对象存储和经验证的 Relay callback 仍由部署人员准备；这些基础设施是初次部署条件，不是每个用户再注册一套 AiToEarn。账户授权页面仍待完整接入。

## 额度行为与限制

- 默认每日 2,000,000 Token，上海时区零点开始新账期。一次请求跨日仍在发起日结算。
- PostgreSQL 原子条件更新保证并发请求不重复占用额度；每次请求先预占输入估算及该请求声明的最大输出 Token（未声明时为 4096），收到服务用量后释放预占、按实际用量入账。
- 输入预估使用请求字节数，**不等于精确 Token 计数**。远程图片、隐藏推理等可能超过预估，实际结算允许超过限额，之后拒绝新请求。这是防失控的调用预算，不是供应商账单的绝对硬上限。
- 超时、断流、缺少 usage、结果未知的请求保留预占，直到次日不再占当天可用额度；历史记录仍保留。没有自动猜用量或自动放行。后续人工核账工具尚未实现。
- 只有明确的 HTTP 429/502/503/504 且尚未转发任何输出时，最多尝试一次备用档位；原请求仍保留预占，以防供应商已经计费。连接超时/流式错误不会重试；图片/视频创建不自动重试；不会重跑整条内容流水线。
- 图片生成、图片编辑、视频生成、轮询、下载沿用原适配器，通过白名单转发。创建请求中的 model 由企业 image/video 选项覆盖；图片编辑保留上传文件并重建 multipart 请求。运营任务提示同时携带企业媒体模型选项。文字 Token 上限**不限制图片张数、视频秒数或金额**。旧 AWS 自定义助手走原计量路径，不计入此账本。
- 原 AiToEarn 一个企业一套服务、共用内部服务用户。目前经它产生的模型调用计入企业、运营部，`user_id` 为空；不能宣称已完成逐用户收费。Office 原生部门接口能记录发起用户。上线收费前仍需把原工作流的用户/任务上下文传到每次调用。
- 私有模型转发只接受由企业 bridgeSecret 派生的内部令牌；真实模型供应商密钥只在主 Office 网关中使用。平台中转密钥只返回给持有当前企业签名密钥的私有运行服务。企业页面不能指定任意环境变量名、内网运行地址或转发目标。

## 本地与服务器部署

主 API 先运行迁移 006，给现有应用角色授予新表权限。现有 bootstrap 脚本会处理，旧数据不删表。

AiToEarn 仍需独立 MongoDB/Redis/素材存储以及已构建的 server、ai 服务。原始数据库及工作流保留。导出配置后可运行：

```sh
node --env-file=.env scripts/export-operations-runtime.mjs <企业UUID>
node --env-file=.env scripts/run-operations-service.mjs <企业UUID> server
node --env-file=.env scripts/run-operations-service.mjs <企业UUID> ai
```

这些命令要求已准备私有注册表、数据库和构建产物；当前没有自动创建运行环境。导出文件不含 AI/Relay 明文密钥，但基础设施连接配置仍是私有文件，禁止提交 Git。

未来 ECS Fargate 部署应把企业密钥通过 AWS Secrets Manager 的任务环境注入；不要放 Terraform 明文变量/state。OfficeOrigin 在容器中必须是可达的主服务地址，不能指向容器自己的 localhost。域名、网络隔离、公开平台 callback 与 CloudFront 路由需要在原基础设施方案中继续接入。本次未部署 AWS，也未验证完整 AiToEarn 容器构建/运行、真实模型生成或真实平台发布。

## 验证方式

自动化测试使用本地 PostgreSQL WASM 引擎和模拟供应商响应，覆盖租户权限、并发预占、幂等结算、备用档位、两种 SSE 用量协议、未知用量保留、私有令牌及环境变量隔离。模拟响应通过不代表 4YI 在线模型或完整制作发布已验证。

## 运营工作台入口

技能库将 600 项目录归为「单体技能包」，底部「流程技能包」用紧凑卡片显示「运营流程」。办公室点叶凡、智能体中的叶凡、技能库卡片与秘书转交都打开同一个原生 dialog 弹窗；关闭回到原页面，在同一企业内保留当前草稿和制作状态。配置只在统一设置中管理，弹窗没有独立连接入口。

秘书页面保留「交给运营工作台」手动入口；只有明确“打开／进入运营工作台”才直接跳转。“让叶凡制作”等工作要求进入秘书规划，用户确认后，后台等待前置任务全部完成，再把实际成果交给运营服务，无需用户守在页面逐项启动。未完成依赖不能提前执行；任务详情可查看前置状态、已接收成果及下载链接。运营服务未部署、模型失败或交接失败会显示实际阻塞原因，不标记为已完成；已提交或结果未知的任务不会重复创建。对外发布仍遵循下方审批规则。

## 发布确认的实际边界

按最新需求，原 createChannelPublishFlow 工具只创建待确认申请，execution_mode=manual。管理员在运营工作台核对内容、媒体、目标账号和时间后点击“通过发布”，后端记录 approved_by 并原子提交一次。拒绝不会触发上游；相同内容与计划去重。网络超时等结果不明确时保留 uncertain，不自动重发。submitted 只代表原服务已接收，平台是否成功仍须回执确认。旧版自动发布运行服务需升级为调用桥版本 4；不能仅修改模型提示词来代替服务端发布限制。

## 私人秘书个人配置与对话

`GET /api/tenants/:tenantId/secretary` 返回任务、对话和个人偏好；`PUT .../secretary/preferences` 保存性别形象、名字、称呼、语气、回复长度和习惯。数据库迁移 008 在现有表新增 preferences，继续使用企业与用户双重行级隔离，原任务与对话保留。

`POST .../secretary/chat` 在服务端读取保存的偏好及最近 20 条消息，调用 secretary 部门配置的文字档位，复用企业密钥、Token 预算及用量结算。有效回复才写入对话；模型生成任务时校验部门、日期与数量后保存为草稿，原有修改与派发交互保留。没有密钥或模型时明确报错，不回退到示例答案。男女切换不改变企业模型和部门员工。

页面移除了体验示例与旧的本地调试助手编辑器。确认派发后由后台任务队列执行，真实状态与成果写入数据库；对话建议或任务草稿不代表已经执行。定时提醒与工作执行分开，提醒本身不会发布内容。运营部手动入口仍是同一个工作台。

验证：分类元数据和名称识别、旧配置兼容、JSON 图片/视频与 multipart 图片编辑的实际出站参数、个人偏好持久化/隔离/系统提示词、模型草稿校验均有自动测试。浏览器验证男女切换、保存刷新和中英切换。真实供应商聊天和媒体生成需配置用户密钥后再联调。
