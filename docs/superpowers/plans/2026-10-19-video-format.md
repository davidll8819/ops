# 叶凡视频规格修复 Implementation Plan

> **For agentic workers:** Use executing-plans inline and test-driven-development. One final fresh review.

**Goal:** 现有弹窗可选择视频比例和清晰度，规格进入实际生成调用；结果依据实际视频尺寸验收。
**Architecture:** 可选 videoFormat 从 Office 请求传入原制作任务并持久保存，媒体工具强制应用用户选择，FourYi 适配映射服务商参数并探测已保存视频。保留既有自动要求路径。
**Tech Stack:** React/TypeScript, Node.js, NestJS, MongoDB, FFprobe.
**Spec:** 用户本轮要求及本计划。不修改办公室动画，不更换企业模型，不以裁剪或拉伸冒充原生生成。

## Constraints and decisions
- 无 Git HEAD；保留所有现有文件，用本次文件快照而非提交/清理验证。
- 规格显式选择优先于模型自行填写；未选择时沿用工作要求。初步范围为当前 Wan 的 9:16 / 16:9 / 1:1、720p / 1080p；未获证实的组合不宣称已实测。
- 不重复提交未知结果，不自动生成第二份补救素材；先使用一个 5 秒任务验证服务商参数映射。
- 真实尺寸不匹配时保留原素材并明确标记规格未通过，禁止虚报。

## Review focus
- 界面选项必须到达实际视频调用，恢复历史任务不使用另一任务的新选项。
- 服务商请求字段及响应符合真实证据，不能以 mocked 成功代替实测。
- 完成任务中的视频必须保留各自请求规格、实际尺寸、验收结果。
- 未选规格和旧任务继续兼容，异常查询不会触发第二次付费生成。
- 已有数据、办公室文件和弹窗行为保持。
