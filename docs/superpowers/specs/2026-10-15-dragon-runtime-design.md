# 龙傲天独立执行工作区

用户选择先建立独立工作区，要求龙傲天实际修改文件、运行代码和测试，保留现有 Wishtaday 和办公室动画。

本阶段由开发者选择以下实现：在现有员工弹窗增加“项目工作区”，在对话中显示“在项目工作区执行”开关。每个企业、用户各有一个龙傲天工作区；只允许企业 owner/admin 执行。现有普通对话保持可用，后台其他部门任务不自动获得代码执行权限。

项目源文件持久化在数据库中，每次命令把当前快照送入一个短期 Docker Linux 容器，再保存实际产生的新快照。这样容器不挂载宿主目录、Docker socket 或密钥，也不会接触办公室源文件。首版提供 Node.js 24、npm、Python 3 和标准库测试工具；网络关闭，外部依赖安装和网页服务预览留到后续。

文件工具：列出、读取和写入 UTF-8 文件；命令工具：在 /workspace 执行 shell 命令。每次命令最多 60 秒、512 MiB 内存、64 MiB 工作目录、32 MiB 临时目录、128 个进程、1 CPU。持久化快照最多 200 个文件、单文件 1 MiB、总计 8 MiB。二进制文件保留并可下载，文本读取拒绝二进制。符号链接不跟随；超限快照不会覆盖已有项目。

执行前领取持久化运行标识并锁定工作区；每步执行意图和结果单独记录。请求失败或页面关闭不会把已修改文件伪装成没发生；用户能刷新查看运行日志。相同对话版本不能重复运行；失去权限或执行租约时停止后续操作，不自动重试命令。允许重新发起新工作，但保留上一轮错误和实际产物。

项目页显示环境状态、文件列表/内容、整个项目 ZIP 下载和最近执行记录。每个命令显示退出码、输出、超时/截断状态；模型不能仅凭文字声明测试通过。Superpowers 继续通过 read_skill 读取，新增工具提供实际执行证据。

本机部署启用 Docker 驱动；没有预构建执行镜像或 Docker 的部署明确显示不可用，不退回宿主机 shell。执行镜像单独构建，不改应用生产 Docker 的权限或挂载。

验收：真实模型在工作区内创建一个小函数和测试，实际运行失败测试、修复文件后跑通；文件及日志刷新后仍在；下载内容与工作区一致；权限、租户、并发、超时、快照边界和失败保存有自动测试；办公室 40 个基线文件哈希不变。
