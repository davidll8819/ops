User approved adding old/new document comparison, highlighted differences and a change summary in the existing Zhao popup. They also explicitly requested a larger popup with department conversation on the right, more history and input space. Office animation must remain unchanged. This implements that request directly; ordinary technical decisions below are builder choices, not additional user requirements.

- 开始比对 immediately produces a persisted deterministic comparison and count overview. Show unchanged content only on request, paginate at most50 rows per page. Added green + 新增 label, removed red + 删除 label, modified old/new inline highlights + 修改 label. Each side shows filename/role and actual paragraph/page/cell-range location. No color-only meaning. If inline refinement exceeds its budget, display whole-block replacement clearly, retaining all text.

Switching files/comparison/tenant invalidates stale responses, never relabels an old result as a new pair. Saved comparison messages allow 查看本次比对 and reopening a historical result. A model failure leaves the full deterministic comparison intact and uses existing safe model-error behavior (no automatic retry).
- Comparison history: latest20 lightweight entries. Results survive close/reload; comparisons and their source identity are immutable. Repeating an ordered extraction pair returns the same comparison; reversing direction produces a different result.

## Meaning and limits
- Compare exact extracted text, not typography, page appearance, embedded artwork, Word tracked-change history or XLSX formula expressions with identical cached values. Block order matters; location/block numbers are provenance, not matching keys. A moved paragraph may appear as removal/addition. Exact whitespace changes remain visible; no NFKC/whitespace folding for equality. No-change wording is 已提取文字未发现变化, never 文件完全相同.
- Existing parser bounds stay: source6MiB,200000chars/2000blocks/2000chars-per-block; PDF120pages/10OCRpages. Never reparse ready inputs. Read both full extractions, not question-ranked excerpts. Verify original source SHA before create/detail/model context. Cross-user/tenant access returns404; unready409; same-file400; stalehash409.
- Diff algorithm text-diff-1: deterministic exact-block LCS with integer token IDs, maximum2000x2000 cells (~8MiB Uint16). Stable tie break; ordered unmatched runs pair into modifications, then grapheme-level inline LCS after common prefix/suffix stripping. Global inline-cell budget2000000; excess becomes explicitly block-level highlights, never content truncation. Source/algorithm bounds validated; serialized comparison result <=6MiB or fail with split-file instruction. No new dependency/network for comparison. Keep calculation/model calls outside DB transactions.
- Preserve extraction warnings, OCR caveats and differing-parser-version notice. Summary uses only actual changed hunks; max32 sources/24000 source characters, keep both sides of a modified hunk together. If only a subset fits, report included/total changed counts. Never call the selected snippets a full semantic audit. No changes => deterministic no-change response, no model call.

## Exact interfaces
Pure module apps/api/src/archive/compare.mjs exports compareDocumentText(oldDocument,newDocument), receiving ready-like objects with blocks and returning {algorithmVersion:'text-diff-1',stats:{added,removed,modified,unchanged},overview:string,warnings:string[],hunks:ComparisonHunk[]}.

ComparisonHunk={id:string,type:'equal'|'added'|'removed'|'modified',granularity:'inline'|'block',old:ComparisonSide|null,new:ComparisonSide|null,oldSegments:Segment[],newSegments:Segment[]}; Side={blockId,location,text,method?:'ocr',page?:number}; Segment={text:string,changed:boolean}. Each side is an entire original block, segments concatenate exactly to its text; absent side => empty segments. Equal aligns exacttext despite changed locations. IDs h1,h2,... stable in full result. Overview counts changed block-pairs, not individual word edits. Do not combine blocks beyond2000 or invent offsets.

ComparisonSource={fileId,name,extractionId,sha256,parserVersion,kind,ocr:boolean}. Comparison={id,createdAt,oldVersion:ComparisonSource,newVersion:ComparisonSource,algorithmVersion,stats,overview,warnings,hunks}. ComparisonReference omits hunks/warnings but includes id,createdAt,oldVersion,newVersion,stats,overview,algorithmVersion. API:
- POST /api/tenants/:tenantId/archive/comparisons {oldFileId,newFileId} -> {comparison}
- GET .../archive/comparisons -> {items:ComparisonReference[]} newest20
- GET .../archive/comparisons/:id -> {comparison}
- Existing POST .../departments/archive/chat accepts optional comparisonId mutually exclusive with fileIds/image/projectId; other departments reject it. Existing revision semantics remain.
- Saved user/assistant messages optionally include comparison:ComparisonReference. Comparison citations retain existing identity/quote fields and add server-owned comparisonId,changeId,side:'old'|'new'. UI displays 旧版/新版. For every modified hunk mentioned by a model claim, validate citations include both old and new sources from that hunk. Never accept model-supplied hash/name/location/side. Reuse existing strict JSON/quote verification; compare context attaches server-only validation metadata.
