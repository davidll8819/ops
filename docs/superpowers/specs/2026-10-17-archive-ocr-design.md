# Zhao document OCR with traceable answers

User authorization: extend the existing Zhao Yameng/file-agent popup to read scanned PDFs and images, ask questions after recognition, and cite the source. Do not change office animations. The prior document-chat experience, private file ownership, selected-file question scope and immutable citations remain the foundation. This is the approved next increment, not a replacement interface.

## Product behavior
Upload DOCX, PDF, XLSX, PNG, JPG/JPEG or WebP through the existing panel. Supported image uploads use extension-derived canonical MIME for the existing authenticated raster preview route; parser validates actual signatures/decoding independently. Retain 6 MiB per file, 100 MiB personal storage, at most four selected ready files. Show real parsing/OCR stage and current page while processing, including a new upload before its long parse request finishes. Closing/reopening a popup does not cancel server work. Retry failed work; don't run duplicate active work.

PDF pages without useful extractable text are rasterized and OCR'd; mixed text/scanned PDFs keep real page numbers. Handle a scanned page with a small text header/footer as scanned too. Automatic decision: OCR when there is zero extractable text, or when a page has raster images AND either fewer than40 non-whitespace text characters or an image covers at least25% of the page (derive painted image area from PDF operator transforms). Pure short text pages withoutimages retain fast text extraction. Smaller embedded illustrations on otherwise textual pages are outside automatic OCR and disclosed. No fabricated completeness claim. Word embedded images, handwriting guarantees, layout reconstruction, OCR text editing and version comparison are outside this increment.

Show OCR warnings visibly: recognition may contain errors, especially numbers/handwriting/blur; inspect the original. Empty/undecipherable image fails clearly. A blank PDF page produces a page-specific warning if other pages contain text; all-blank fails. A failed OCR engine/rendered scan must fail the whole extraction, not quietly omit a scanned page. No silent truncation on limits. OCR sources use actual `第 N 页（OCR）` or `图片第 1 页（OCR）`. Text PDFs retain existing `第 N 页`. Sources can show original images through the existing private preview route after identity/quote validation; PDFs retain original download and page location. No PDF inline renderer is needed in this increment.

## Implementation decisions (builder defaults, not user-specified)
Use local Tesseract.js 7.0.0, bundled `@tesseract.js-data/eng` and `chi_sim` 1.0.0 production packages with explicit local paths and no runtime downloads or persistent cache writes. A private temporary job directory may stage the two trusted bundled language files so Tesseract's public string-language API can read one local langPath; cacheMethod:none and finally cleanup after workertermination. Never modify node_modules. Validate the ownedtemp path before recursive cleanup. This avoids an observed upstream object-language initialization bug. Use existing PDF.js and explicit production `@napi-rs/canvas` 1.0.11. OCR detects Chinese simplified and English together. Ordinary question answering uses the existing archive text model after OCR; no gateway/provider configuration changes.

Keep extraction in a disposable Node child process so timeout/kill also destroys canvas/WASM and nested OCR worker threads. Max two active parser processes globally; queued excess rejects visibly. Parent process remains responsive. DOCX/XLSX budget stays 30 seconds; PDF/images total budget 300 seconds. OCR language worker is reused sequentially within one file and terminated in finally; no child process survives timeout, success, failure or app close. Parent creates an ownedtemporarybase, passes ARCHIVE_OCR_TMPDIR to child, and removes thatbase afterchildexit evenonforcedkill. OCRhelperstagesitsprivate languagedirectory underthatbase (or os.tmpdir forstandalonehelpertests). Childenvironmentcontains onlyrequiredsystempath/temp variables andthisbase, notDB/APIcredentials. Local dependencies contain all runtime resources and work after npm ci/prune in Docker.

Bounds: source 6 MiB; input raster at most 12 million pixels and 12,000 pixels per side (check headers before decode, validate after too); reject animated/multipage raster formats. Rasterized image/page target max 3,000 pixels per side and 5 million pixels, white background, sequential allocation and explicit canvas cleanup. PDF page count remains120, OCR pages at most10; max total rasterized OCR pixels50million. Exceeding any OCR limit fails with split/rescan guidance. Retain 200,000 chars, 2,000 blocks, 2,000 chars per block, Unicode-safe splits, ZIP/Office protections. OCR confidence below60 yields a location-specific warning, not an unsupported numerical accuracy promise.

## Contracts
`extractDocument({name,bytes,onProgress?})` remains async and returns `{kind,blocks,warnings,stats}`. Add kind `image`; add optional block fields `{method:'ocr',page:number}` only for OCR. Stats include bounded `ocr:{engine:'tesseract.js',version:'7.0.0',languages:['chi_sim','eng'],pages:number,lowConfidencePages:number[]}` when OCR was used. No originals or secrets in progress/logs.

Progress callback receives `{stage:'extracting'|'ocr',page:number,totalPages:number}`; values reflect current page, not invented percentage. Parent accepts only bounded valid progress. Public Document adds optional `progress` for processing (a dedicatednullableDBcolumn) and `ocr` (boolean) for ready records projected from stats; existing blocks may omit method. GET list must not expose full text. Worker function `createDocumentParser({timeoutMs?,ocrTimeoutMs?}={})` returns parser `(input,{onProgress?}={})` plus `.close()`; test overrides keep timeout/capacity tests fast. Parent callback persistence is ordered and flushed before final completion; late updates cannot modify ready/new attempts.

Retain awaited POST `/archive/documents/:fileId/parse` body `{}` and existing JSON result; add parse route to existing slow-response heartbeat allowlist, avoiding a new background-job service. UI starts polling the known uploaded file while POST is pending (refresh membership before parse, poll local busy IDs as well as server processing). No long DB transaction. Lease for PDF/images360seconds, other files90seconds. Attempt ID and unexpired lease fence both progress and completion. App close terminates owned processes and awaits safe cleanup; retries after restart recover by existing lease mechanism.

Add migration017 broadening kind CHECK to image and allowing parser_version changes only for non-ready records. Preserve FORCE RLS, tenant+user identity, SHA256 and ready immutability. New/retried failed extraction parser_version archive-2; existing ready records and historical quotes never change. Old ready mixed PDFs require reupload to incorporate new OCR; show a concise hint in document tools. Source bytes stay in workspace_files unchanged.

Grounding preserves exact normalized source quote checks and server-derived identities. Pass OCR caution into source context and persisted answer coverage. Citations may add optional `method:'ocr'`/`page:number` from server block only so historical OCR quotes remain labeled without trusting model metadata. Build context warns that OCR is transcription and must not silently correct numbers. Saved quotation is labeled `识别文字摘录（OCR）`, distinct from a guaranteed perfect original transcription. Preview still checks file/extraction/hash/block/location/quote; original image URL only after verification. Tenant/user isolation and unselected-file exclusion unchanged.
