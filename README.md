# Wishtaday · AI Office

在 ai-office-react 原项目上改造的本地可运行 SaaS 工作台。AWS 部署已开始准备，**目前仅创建了私有 Terraform 状态存储桶，业务站点尚未上线、网站 DNS 尚未切换，也没有开启实际扣款**。最新进度见 [部署说明](docs/DEPLOYMENT.md)。

## Windows 下载与使用

办公室 Windows 用户先看 [Windows 从这里开始](WINDOWS-开始使用.md)，完整步骤见 [安装与 Mac 数据迁移说明](docs/WINDOWS-SETUP.md)。从 [Releases](https://github.com/davidll8819/ops/releases) 下载完整包，可获得代码和 600 项目录对应的 149 个技能归档；GitHub 自动源码 ZIP 不含技能归档。安装 Node.js 24 和 Docker Desktop 后，双击 `Setup-Windows.cmd` 安装、`Start-Windows.cmd` 启动。迁移旧数据须在首次启动前恢复私有备份。

## 最新入口（2026-10-12）

新增独立“任务成果”和“资料室”，秘书台支持图片／文本附件及带来源的新闻简报；公司模型增加搜索能力，部门可分别启用图片、视频、搜索并继承或覆盖公司模型。具体数据流、文件位置及验证边界见 [成果与模型能力说明](docs/results-and-capabilities.md)。下方早期阶段的测试记录保留作历史记录。

任务接续现由后台持久队列负责：确认派发后，按前置任务关系执行，网页关闭后仍可继续。设计可以生成文字方案、分镜或真实图片；已完成的文案、图片与来源交给后续部门，任务详情显示前置状态和“已收到成果”，完成结果自动归档。运营服务就绪后，叶凡携带前序成果自动接单，后台同步原服务状态；对外发布仍需单独审批。当前企业独立 AiToEarn 服务尚未部署，原茶叶任务已收到设计成果并明确阻塞于此，没有重做原设计或新增模型调用，真实视频与平台发布尚未验收。

## Mac 本机使用

1. 双击 `Start-Local.command`，浏览器打开 http://localhost:3000。
2. 账号和随机密码在 `.local/login.txt`。管理员 `owner@local.test`，普通成员 `member@local.test`。
3. 登录后默认进入办公室。点击人物或场景上方名字，可切换工作状态、23种表情或选择同事互动；可暂停、继续、切换自动演示和恢复初始场景。
4. 管理员已有“本地企业联调”和“个人工作空间”，可在顶栏切换。语言按钮支持中文 / English，刷新后保留选择。
5. 双击 `Stop-Local.command` 停止应用和本项目数据库、缓存容器，数据卷保留。

已安装 Node.js、Docker/Colima 与 npm 依赖。迁移到另一台电脑时，需要先安装 Node.js 24、Docker 和 npm ci；`.env`、`.local` 是本机配置，不提交 Git、不复制到公开位置。服务和数据库端口只绑定 127.0.0.1。

本地可以调试：登录、退出、租户切换、个人/企业权限、成员邀请链接、手动助手配置、Harness 参数导出、原项目动画、中英文切换、用量展示。

企业 API Key 和模型档位配置后，秘书与部门对话直接使用企业模型，无需 AWS。连接 AWS 后才能验收：Agent builder 自动生成、AgentCore 记忆、云端 Cognito 密码及 Passkey 登录。未连接时页面明确提示，模型调用返回未配置错误，不返回模拟答案。费用界面当前是用量账本，**不代表已经支付或扣款**。

## 任务进度与工具位置更新（2026-10-11）

办公室右栏使用任务卡片及当前/历史切换，不再展示聊天或快捷工具。卡片按部门区分颜色，显示负责人、截止日期、真实执行阶段、阻塞原因；展开可看文字结果或进入已关联运营任务。阶段条不是生成百分比。互动开关在画面上方，语音入口在私人秘书输入区，文件及屏幕截图/OCR 在资料室员工详情。

秘书没有真正创建任务时显示明确提示，提供整理分工入口，并拒绝将空任务的模型答复当作分工成功。新任务保留完整要求。运营任务启动后把原运行服务任务编号绑定到私人任务记录，轮询原状态；事件流结束不能等同于任务成功，也不能等同于平台发布成功。未知提交结果阻止重复创建。此前只有聊天、没有任务记录的内容不会自动补派发或产生模型费用。

验证：71 项测试通过，包含任务约束保留、空分工校验、运营任务绑定/状态同步/防重复。实际浏览器验证工具迁移、语音文本回填、当前与历史切换和中英文；未启动真实付费生成或对外发布，也未申请麦克风/屏幕捕获权限。

## 本轮功能联通（2026-10-11）

- 办公室人物可进入对应部门工作台；叶凡打开运营工作台。统计和任务流改为当前用户真实任务记录，模型就绪数来自企业配置，不使用演示数字。
- 部门对话按企业档位调用模型，记录私人历史与词元用量。秘书任务确认分工后执行文字部门任务，显示完成结果或失败原因；视频发布任务转入运营流程。
- 已安装技能可查看原文并分配给部门。对应对话及文字任务读取已分配的说明；运营任务也会带入运营部技能说明。脚本、终端和联网工具不会因安装说明文件自动获得执行能力。
- 文件工具支持上传、列表、下载；按企业与用户隔离，单文件 6 MB、个人空间 100 MB。当前用数据库存储小文件，视频素材继续属于运营服务的对象存储。
- 图片文字识别使用资料室文字档位的图片输入能力；需选择支持图片输入的模型。语音由浏览器提供识别服务，可编辑后转交秘书，需浏览器支持与麦克风授权。
- 提醒在助手配置中保存，可单次/每日重复和取消；服务器每 30 秒检查，到时写入私人秘书对话。提醒不等于执行或发布任务，服务停止期间无法准时送达。
- 运营工作台新增账号列表、授权入口和授权状态检查。依赖企业运行服务与平台中转密钥；多级账号选择、真实 OAuth 回调及平台发布仍需原服务联调，不标记为已验收。

验证：70 项自动测试（含模型模拟传输、多租户权限、任务执行、防重复、文件隔离、技能分配、提醒幂等），以及构建和静态检查通过。实际页面已验证文件上传、人物跳转、技能分配保存、提醒保存/取消、语音文本转交、中英切换和缺少密钥时的设置跳转。没有调用收费模型、使用真实麦克风或发布到社交平台。数据库迁移 009/010 保留旧数据；本地服务已运行。

## 项目地图

这是给个人及企业团队使用的智能办公室：一个账号可进入不同企业，企业内部共享助手配置，聊天及记忆按企业、用户、助手隔离。

```text
浏览器 → 中英文 React 界面 → Fastify API（登录、权限、计量）
                               ├─ PostgreSQL：账户、企业、成员、助手、对话、用量
                               ├─ Redis：登录会话、限流、缓存、调用锁
                               └─ AWS AgentCore：共享 Harness + 每次调用的 profile
```

云端在入口增加 CloudFront CDN（静态资源就近缓存），业务进入香港 ECS Fargate ARM 容器。RDS PostgreSQL 和 ElastiCache Redis 位于私有网络。Cognito 管理云端账户。AgentCore 和记忆位于 us-west-2，可改 us-east-2，禁止香港。

## 文件结构

- `apps/web`：React 界面；原有 Pixi/Spine 场景保留，新工作台在 `src/saas`，语言在 `src/i18n`。
- `apps/api`：登录会话、企业权限、数据接口、计量及 AWS 适配。
- `apps/runtime`：原生 AgentCore Harness 参数编译与调用上下文；不再按每个助手建一个容器。
- `packages/contracts`：前后端配置约束，拒绝用户注入工具、执行角色等基础设施参数。
- `skills`：单项技能（`capabilities`）与流程技能包（`workflows`），各有独立编写模板；使用方式见 [技能目录说明](skills/README.md)。已安装并分配的技能说明会进入部门提示词；不自动运行技能中的任意脚本。
- `database`：数据库迁移及最小权限角色初始化。
- `infra/terraform`：六个云端模块；`infra/bootstrap`：部署状态存储桶。
- `scripts`：本机启动、初始化、企业版人工开通及未来镜像发布/迁移。
- `tests`：租户隔离、记忆标识、权限与重复请求计量测试。
- `docs`：复用方案、AWS 部署步骤和验证边界。

开发时 `npm run dev:web` 启动前端开发服务器，`APP_ORIGIN=http://localhost:5173 npm run dev` 启动 API（先停止已运行的本地应用，并从 http://localhost:5173 访问开发界面）；日常使用双击启动脚本即可。构建 `npm run build`，检查 `npm run lint`、`npm test`。

## 数据与账户

本地调试账号只适用于 localhost；生产模式拒绝开启本地认证。未来 Cognito 账号以身份服务的稳定 subject 标识，不会仅因为邮箱相同就合并本地测试账户。默认云端新建干净数据库；需要带走本地业务数据时，先备份，再执行单独的账户映射迁移，不能直接复制本地密码到 Cognito。

成员邀请链接由管理员复制给受邀人，不会自动发邮件。只有相同邮箱的已登录用户可接受，邀请七天过期、单次使用。企业版目前由运营手工开通；支付宝、微信及订阅扣款后续接入。

请勿运行 `docker compose down -v`，它会删除本地数据卷。备份/恢复与云端上线见 [部署说明](docs/DEPLOYMENT.md)。

## AiToEarn 运营部接入（本地集成阶段）

产品路径：用户登录 Office → 选择企业 → 智能体 / 叶凡 → 运营工作台 → 原 Agent（智能体）任务 → 原生成、剪辑、素材工具 → Office 发布确认与记录 → 原平台发布服务。

已落地：

- `integrations/aitoearn/source`：保留原后端、前端、MongoDB Schema（数据库结构）、业务算法、技能和许可证。2635 个来源文件有 SHA-256 清单；其中 8 个启动/配置及 Relay 入口增加 Office 适配、环境变量解析与企业密钥读取，另移除了原初始化脚本的默认认证密钥。原工作目录不变，原用户数据与令牌没有导入。
- `apps/api/src/operations`：企业设置加密、独立运行服务校验、原 Agent SSE（事件流）转接、发布审批及重复提交保护。
- `apps/web/src/saas/operations`：运营工作台。设置在原“设置”中，流程入口也登记在技能库。中英文切换沿用全站设置。
- `database/migrations/005_operations.sql`：企业配置、发布记录与调用审计；沿用 PostgreSQL 行级隔离。AiToEarn 的 MongoDB 仍需独立部署，不把它的复杂结构强行改写为 PostgreSQL。
- `skills/workflows/aitoearn-content-pipeline`：内置服务型流程的约束；不是安装一个 Markdown 就能生成视频。

企业自带 AI 密钥。AiToEarn 的 provider/Relay 配置原本是进程级全局配置，因此第一版每个企业使用独立的 server + ai 运行服务、队列及 Mongo 数据库。这保留了原算法，增加了企业数量增长时的运行成本；将来共享运行服务需要单独改造原配置依赖，不能直接复用一个实例或切换全局密钥。

部署准备（由维护者执行，用户不需要第二次注册）：

1. 企业管理员在设置页填写 AI 与平台中转 API Key，分别加密保存且不回显。留空保留，更新后运行服务动态读取。部署默认环境变量仍可用，已保存的企业密钥优先。加密主密钥 `.local/operations-config.key` 需与数据库分别备份；云端由 Secrets Manager 注入，禁止把密钥写入 Terraform state。
2. 根据 `integrations/aitoearn/runtime-registry.example.json` 准备受保护的 `.local/operations-runtimes.json`。示例不能直接用于生产。每个企业分别配置私网端点、随机认证密钥、MongoDB replica set（支持事务的数据库副本集）、无逐出队列 Redis、对象存储。主应用数据库及其它企业不需要重建。
3. 从所复制源码构建原 server 和 ai 镜像；保留原 Agent 技能资源、Claude Code Router、ffmpeg 和任务 session 文件的持久化。不能使用不含 Office 发布审批适配的上游现成镜像，连接检查会拒绝它。
4. `node --env-file=.env scripts/provision-operations-user.mjs <tenant UUID>` 仅在新的专属数据库创建内部服务身份，无密码、无第二次注册。该命令不会导入原账号。
5. `node --env-file=.env scripts/export-operations-runtime.mjs <tenant UUID>` 将该企业当前版本的配置写入 `.local/operations/<tenant UUID>/{server,ai}.yaml`，权限 0600。导出的认证及 AI/Relay 字段是环境引用，启动时按 `scripts/run-operations-service.mjs` 注入。挂载到对应服务并重启后，工作台检查两端企业编号、版本及发布审批适配。首次升级需使用版本 4 的运行服务，之后更新密钥与档位不需要重新导出。
6. 两个运行服务仅对主应用私网开放，不暴露原注册、配置编辑器或内部接口。AI 服务访问 server 时保留 Office 签发的租户身份；发布签名密钥不可给模型或浏览器。主应用只开放明确的任务和审批接口。

验证边界 / 尚待完成：

- 已做本地传输、加密、权限、数据库隔离和发布拦截测试；没有执行收费模型生成，也没有绑定真实平台或对外发布。
- 原平台授权、素材浏览、视频编辑页面的源码已保留，但这些完整页面尚未嵌入 Office。当前工作台提供原任务对话与发布确认记录。OAuth / Relay 回调的公网地址、状态校验及平台实测仍需接入，不能把“源代码存在”说成“全流程已上线”。
- 原字幕工具在当前 Agent 注册处被上游注释，不能声称已经启用。部分剪辑工具还依赖额外的服务商配置，一把 4YI 密钥不代表所有工具都可运行。
- `submitted` 只表示原发布服务接收任务，不等于平台发布成功。超时进入 `uncertain`，禁止自动再次发布，须查询原 flowId 的回执。尚无本页自动回执轮询。
- 企业服务目前尚未部署；现有主应用 Terraform 未扩展为这些独立运行服务、MongoDB、媒体存储和授权回调。香港 Fargate ARM 上的原依赖兼容性、镜像构建、队列持久化和费用需在该部署阶段验收。AgentCore 仍按原约定只放美国区。
- 企业 AI 使用费用由其服务商直接扣费。统一入口现在记录文字用量及每日预占；图片/视频金额和 AiToEarn 逐用户分摊仍未接入，不能据此宣称已完成收费账本。

源码核对：`node scripts/verify-aitoearn-source.mjs`。主应用检查：`npm run build`、`npm run lint`、`npm test`。发布安全测试同时执行原源码新增的审批 middleware（请求拦截层），并非只检查界面按钮。

### 企业统一模型配置

设置页面支持企业模型入口、strong / fast / cheap 文字档位及 image / video / search 专用能力、部门技能引用和每日文字 Token 预算。凭据在设置页填写并按企业加密保存。用户确认分工后，运营任务由后台携带前置成果提交已部署的独立运行服务；对外发布仍须审批。配置样例见 `config/company.example.yaml`，调用路径、部署准备与未验证边界见 [企业模型入口说明](docs/company-model-gateway.md)。

## 秘书 → 市场调研 → 资料室（第一条派活链路）

- `apps/api/src/research/plan.mjs`：把模型草稿转成有依赖关系的任务，并补充资料室归档任务；用户确认后与任务记录一起写入任务队列。
- `apps/api/src/research/engine.mjs`：主服务每 3 秒检查持久队列，数据库原子领取任务。网页关闭后继续运行；执行租约过期只标记中断，不自动重复产生模型费用。一个服务进程同时执行一项任务。
- `apps/api/src/research/outlined-agent.mjs`：刘市先用企业指定模型生成调研目录，再逐项检索、读取来源、按目录汇总。目录状态实时写入任务，缺少实际来源或有效引用不能标记完成。资料室模型整理摘要，原报告、来源与检索时间按日期/部门存入现有私有文件库。
- `apps/api/src/research/model-web.mjs`：使用现有企业模型入口的内置搜索。Claude 通过 Messages server tools，其他兼容模型通过 Chat Completions 的 web_search_options；只接收真实搜索事件或结构化来源引用。具体中转通道是否支持须实际验证，普通聊天成功不代表联网可用。无需单独搜索密钥，也不切换外部搜索服务或偷偷更换模型。
- `apps/api/src/research/web.mjs`：复用其中的公共网页读取器，逐次检查并固定公共 IPv4 地址，限制重定向、响应大小和超时，不读取内网。旧搜索适配器保留兼容，但现行执行器不读取或调用它们。
- `database/migrations/011_research_engine.sql`：任务队列、加密的企业搜索配置和待发布记录切换到手动审批。已提交或结果未知的旧发布记录不重跑。
